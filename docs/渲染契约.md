# 中台渲染契约（render block）

中台把"要呈现给用户的互动与内容"结构化为一组 **render block**，任何接入系统的前端
都能按 `block.kind` 映射到自己的组件去渲染。契约是**业务无关、样式无关**的：
中台负责"什么时候触发、数据长什么样"，前端只负责"长得好不好看、怎么排布"。

## 两种产出方式：内联声明（首选）/ 工具（兜底）

### 内联声明（第一等结构化输出，首选）

模型在**正常输出文本**里用 `<render>{json}</render>` 声明要渲染的块，不依赖任何工具槽：

```text
好的，结果如下：
<render>[{"kind":"table","columns":[{"key":"n","label":"名称"}],"rows":[{"n":"张三"}]}]</render>
以上就是查询结果。
```

前端拿到助手完整文本后，用跨项目通用的 `parseRenderBlocks(assistantText)` 统一抽取并校验，
按 kind 渲染即可。支持 `<render>...</render>`、```` ```render ... ``` ````、
`RENDER_BLOCKS= {...}` 三种宽松写法。模型不需要为了"展示"消耗一次工具调用。

### 工具产出（兜底）

`render` 工具（`coreTools.render`）返回：

```json
{
  "ok": true,
  "ui": { "type": "render", "blocks": [ /* RenderBlock[] */ ] },
  "hint": "给模型与工具卡的文本预览"
}
```

- `ui` 当中不要用 `trace / summary / message / error / detail / data` 这几个保留字段，
  否则会被 `summarizeToolResult` 当成优先级字段截断，丢失到前端。
- 工具结果经 artifact 外置后，前端在 `TOOL_CALL_RESULT` 里拿到 `{ ref, toolName, summary }`。
  `summary` 是精简预览（约 200 字），若需渲染完整内容：

  ```
  GET /debug/api/artifacts/:ref   ->  { ref, toolName, result }
  ```

  大负载（表格、图表、Mermaid、长文档）一律走 ref 拉取完整 JSON，前端据此渲染。

## Block 种类（kind）

| kind | 载荷 | 用途示例 |
|------|------|----------|
| `table` | `title?`, `columns[{key,label,width?,align?}]`, `rows[]` | 数据表格 |
| `cards` | `title?`, `cards[{title,value,subtitle?,icon?,tone?}]` | 指标卡片 |
| `chart` | `title?`, `type(bar/line/pie/area)`, `xAxis[]?`, `series[{name,data[]}]` | 图表 |
| `mermaid` | `title?`, `code` | Mermaid 图 |
| `document` | `title?`, `sections[{heading?,paragraphs[],bullets[]}]` | 结构化文档 |
| `choices` | `prompt?`, `choices[{label,value,style?}]`（最多 6） | 用户选项（像 Claude） |
| `markdown` | `markdown` | 纯 Markdown 文本 |
| `link` | `url`, `label`, `mode?(auto/tab/navigate)` | 跳转链接 |
| `notify` | `message`, `level?(info/success/warning/error)` | 页面 toast |

一次 `render` 可给最多 16 个 block，按展示顺序排列（如先 `cards` 总览、再 `table` 明细、
需要时加 `chart` / `mermaid`）。

## 与 show_ui 的分工

- `show_ui`：页面级轻动作（`guide` / `notify` / `open_link` / `choices`）。
- `render`：内容级渲染块，可多块组合、承载结构化数据。

两者共用同一个 `{ ui: { type, ... } }` 传输契约，前端一个 dispatcher 即可处理。

## 用户选择（choices）的交接

choices 块渲染成按钮后，用户点击**不应回传裸文本**（模型只能靠回显猜），而应回传结构化选择：

```text
<CHOICE_SELECT value="是" label="确认" />
```

前端用 `buildChoiceSelection({ value, label, choiceId? })` 生成；中台下一轮在
`normalizeChoiceResponse` 里把该标记改写成类型化输入 `[用户在选择按钮中选择了：确认（value=是）]`，
让模型明确知道用户选了哪个选项。相关工具：`parseChoiceSelection` / `choiceToPrompt`。

## 前端如何消费（伪代码）

```js
// 内联声明（首选）：
const blocks = parseRenderBlocks(assistantText);       // 跨项目通用

// 工具产物（兜底）：
function onToolResult(ev) {
  const envelope = JSON.parse(ev.content);             // { ref, toolName, summary }
  let ui = envelope.summary ? JSON.parse(envelope.summary) : null;
  let blocks = ui && ui.ui ? ui.ui.blocks : null;
  if (blocks && JSON.stringify(blocks).length > 150) {
    fetch(`/artifacts/${envelope.ref}`).then(r => r.json())
      .then(a => blocks = a.result && a.result.ui && a.result.ui.blocks);
  }
  renderBlocks(blocks);                                // 按 kind 映射到前端组件
}
```

用户选择按钮点击 → `buildChoiceSelection(...)` 回传（见上节）。

当前中台自带的演示前端 `public/ai-assistant.js` 已实现 `dispatchUI` 对 `render` 的
最小渲染（table/cards/chart/mermaid/document/choices/markdown），可作为参考与联调样例。

## 实现位置

- 契约与校验：`src/core/render/contract.ts`
- 精简摘要：`src/core/render/summary.ts`
- 内联块解析 / 序列化：`src/core/render/parse.ts`
- 选择交接：`src/core/render/handoff.ts`
- 核心工具：`src/core/render/tool.ts`
- 工具出口：`coreTools.render`（`src/core/tools/index.ts`）
- 选择归一化接入点：`src/server.ts`（Hermes factory 的 `normalizeChoiceResponse`）
- artifact 拉取端点：`GET /debug/api/artifacts/:ref`（`src/server.ts`）
