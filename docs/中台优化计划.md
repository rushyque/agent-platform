# AI Agent 中台优化计划

> 状态跟踪文档。聚焦中台本身的通用能力、契约一致性与类型精度；
> 不改动演示项目（db-demo / starlink / freight / saleshub）的业务行为。

## 目标

中台定位是"一次做好、通用复用"的能力层。本轮收敛四件事，让中台既保持
"少而通用的能力原语"设计，又作为所有接入项目共享的干净地基：

1. 提供常用能力分组，项目一行引用，不再各自手抄工具清单。
2. 收敛渲染立场：默认文本内联为第一等输出，render 工具降级为可选高级通道，
   消除"全局禁止 vs 项目引导调工具"的自相矛盾。
3. 收敛 choices 单一所有权：归 render（含结构化回传协议），show_ui 只留页面级动作。
4. 收敛中台契约类型精度，消除会传播到所有项目胶水层的 `any`。

## 执行顺序

1. [X] 能力分组：`src/core/tools/index.ts` 新增 `assistantPrimitives` /
   `dataQueryPrimitives` / `presentationPrimitives` 三个常用组合，项目一行引用。
2. [X] 渲染立场：`renderTool` 定位为"可选中级通道"，description 与全局 prompt
   （文本内联第一等输出）表述一致；消除 db-demo 与全局矛盾的方向。
3. [X] choices 收敛：`show_ui` 去掉 choices 模式（schema / description / execute），
   choices 唯一所有权归 render 契约（含 handoff 结构化回传）。
4. [X] 类型精度：中台 core 安全点收敛——`data/backend.ts` 行类型 `unknown[][]`、
   `render/handoff.ts` 用 AG-UI `Message[]` + 具名返回类型；`AgentContext` 保留
   开放结构（项目自定义上下文的正确类型，建议项目用接口 extends）。
5. [X] 验证：`npm run build` 通过；`npm test`（data 四原语 + render 契约）21 用例全绿；
   前端 `ai-assistant.js` 的 choices 渲染与 `ui.type=choices` 兼容分支保留，契约不回退。
6. [ ] 提交中台优化改动。
