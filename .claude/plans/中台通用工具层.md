# 中台通用工具层 · 设计与落地计划

> 目标:把中台从"只有 getArtifact 一个工具"升级为"自带一批高通用度、有设计难点的对话工具",让接入项目开箱即用,并配套修正"激进压缩反致幻觉"等问题。
> 设计依据:本轮多轮讨论 + 记忆 `nl2sql-design`/`context-management`/`agent-platform-architecture`。
> 日期:2026-07-28。

---

## 0. 统一主题

**给模型更多"外部确定性",减少"内部猜测"。** 所有改动都服务于这一根线:

| 内部猜测(幻觉源) | 外部确定性(本计划方向) |
|---|---|
| 压缩过头→丢上下文→脑补 | 压缩折中,留够上下文 |
| 模型脑子里"想"出事实 | 工具优先,事实从工具来 |
| 模糊自然语言输出 | 结构化 schema 锁死 |
| 高温发散 | temperature 压低 |
| 一锤定音不复查 | 关键步骤验证/反思 |

## 1. 架构决策(已与用户确认)

- **NL→SQL 架构:后端驱动**。中台只做「生成 SQL + guardSQL 校验 + 自纠 + trace」;schema 获取与 SQL 执行走后端抽象(`DatabaseBackend` 接口)。中台 core 不耦合具体 DB。
- **附赠默认 mssql 适配器**:基于 `persistence/db.ts` 的 `getPool()`,连 `ai_platform_db`,项目 `AgentConfig.database` 直接取用即开箱可用;项目也可自实现后端(调自己的端点)。
- **语义层:本轮不做**。query_database 先裸用 `INFORMATION_SCHEMA`(后端提供)。语义层留作独立大工程(`saleshub-semantic-layer` 记忆)。
- **验证库:`ai_platform_db`**(金蝶 K/3 ERP,48 表,真实数据)。已实测连通。

## 2. 设计理念(抽自 Claude Code,映射到中台)

1. **能力原语,非业务流程** —— 工具给"能做什么"(查任意库/看任意现状),不给"按某业务步骤做"。
2. **探索(读)与行动(写)分层,探索零成本** —— 感知类随便调、鼓励多用;写工具要 confirm。天然实现"工具优先"。
3. **返回结构化事实,非自然语言总结** —— return `{rows, sql}`,不写"查到了一些订单"。结构化=可验证。
4. **description 是契约,写正例也写反例** —— `Use for X / Do NOT use Y, use Z`。相近工具(如 recall vs getArtifact)互相点名。
5. **给自我编排工具** —— set_note 治长任务漂移;便签是为对抗折叠而存在,**不折叠**。
6. **关键动作配验证回路** —— guardSQL+自纠是内嵌验证;模型层加"查完交叉确认/写完回查"prompt 习惯。
7. **逃生舱克制** —— 通用 http 后置;有专用工具就不用逃生舱。

## 3. 工具清单与契约

| 工具 | 类别 | readonly | 数据来源 | trace | 状态 |
|---|---|---|---|---|---|
| `getArtifact` | 感知 | ✓ | 内存 | — | 已有 |
| `query_database` | 感知 | ✓ | AgentConfig.database | ✓ | 新建 |
| `observe_state` | 感知 | ✓ | AgentConfig.getState | — | 新建 |
| `recall` | 感知 | ✓ | artifact-store+历史 | — | 新建 |
| `get_note` | 记忆 | ✓ | 本线程便签 | — | 新建 |
| `set_note` | 记忆 | ✗ | 本线程便签 | — | 新建 |
| `now` | 记忆 | ✓ | 时钟+可选钩子 | — | 新建 |
| `confirm` | 人机 | ✗ | 流程状态 | — | 新建(异步简版) |
| `runExtract` | helper | — | — | — | 新建(非模型直调) |

### 3.1 query_database(NL→SQL)
- 参数:`{ question: string, limit?: number }` —— 只传自然语言,模型不懂 schema。
- 机制(复刻 saleshub 已验证稿):四步探索(读 schema 定义→`tables`→`columns WHERE table=?`→`LIMIT 5` 抽样)→ `generateObject` 生成 SQL → `guardSQL`(禁 `DROP/DELETE/UPDATE/TRUNCATE/INSERT/ALTER/GRANT` 等)→ 后端执行 → 失败自纠(MAX_ROUNDS=3)→ 产 `ToolTrace`。
- 返回:`{ ok, rows, sql, explanation, truncated?, trace, schemaWarnings }`。
- readonly=true(显式标)。
- 失败/拦截信封:`{ ok:false, ... , trace }`。

### 3.2 observe_state
- 参数:`{ focus?: string }`。
- 调项目 `getState(ctx, focus)`;大体量自动外置 artifact,context 回 `{ref, summary}`。
- 返回:项目自由结构。
- readonly=true。

### 3.3 recall(回看历史)
- 参数:`{ toolName?: string, since?: "last_step"|"this_run"|"thread", limit?: number }`。
- 返回:`[{ toolName, ref, summary, atStep }]`。
- 与 getArtifact 互补:recall 按条件搜,getArtifact 按 ref 精取。先做"工具名+最近N条"。

### 3.4 set_note / get_note
- `set_note { key, content } → { ok }`;`get_note { key? } → 单条/全部`。
- 作用域:本线程(threadId 内存 Map)。跨 run 长期记忆走已有 thread-memory。
- **set_note/get_note 进不折叠白名单**(便签是对抗压缩的锚点)。

### 3.5 now
- 参数:`{}`。返回 `{ iso, ts }`;项目可选 `formatTime(ctx)` 加业务周期。

### 3.6 confirm(异步简版)
- 参数:`{ action, summary, risk?: "low"|"medium"|"high" }`。
- 返回:`{ ok:false, pending:true, message, context }` —— 模型转述,用户下轮回确认/取消。同步版(前端弹框)等前端 SDK。

### 3.7 runExtract(helper)
- `runExtract({ source, schema, instruction? })` —— 项目工具内部 `generateObject` 复用平台 DeepSeek。不做模型直调工具(模型自定 schema 不靠谱)。

## 4. 配套基础设施

1. **`ToolDefinition.readonly?: boolean`** —— policy 优先看字段,`readOnlyToolKeywords` 做兜底。治"起错名致折叠死循环"。
2. **`ToolTrace` 复用** —— query_database 产,未来内部多步工具统一。
3. **`coreTools` 显式取用** —— `src/core/tools/index.ts` 导出 `coreTools.{queryDatabase, observeState, recall, setNote, getNote, now, confirm}` 及 helper。AgentConfig.tools 里显式 import,不全局注入(游戏不查库就不挂)。
4. **AgentConfig 新增可选字段**:`database?`/`getState?`/`summarizeState?`/`formatTime?`。缺哪个不挂哪个工具。

## 5. 压缩折中 + 模型约束

- `DEFAULT_POLICY`:`hotToolResults` 1→**2**;`summarizeThresholdChars` 适度调高(不那么急压);只读不折叠守住;便签不折叠。
- `createLLMClient`:temperature 默认 **0.2**,项目可覆盖。
- 中台级 prompt(`COMPACTION_GUIDE` 增强 + 工具优先约定):事实必须来自工具、不许脑补;探索工具随便用;重要结论交叉确认。
- 验证/反思:query_database 已内嵌 guardSQL+自纠;模型层靠 prompt 约定,不引入强制机制。

## 6. 文件结构

```
src/core/tools/
├── index.ts                  # coreTools 聚合导出
├── query-database/
│   ├── index.ts              # queryDatabase 工具(ToolDefinition)
│   ├── nl2sql-agent.ts       # 四步探索 + generateObject + 自纠 + trace
│   ├── guard.ts              # guardSQL 禁词校验(纯函数)
│   └── backend.ts            # DatabaseBackend 接口 + 类型
├── backends/
│   └── mssql.ts              # 默认 mssql 适配器(复用 getPool,连 ai_platform_db)
├── observe-state.ts          # observe_state + getState 钩子
├── recall.ts                 # recall
├── notes.ts                  # set_note/get_note(本线程 Map)
├── now.ts                    # now
├── confirm.ts                # confirm(异步简版)
└── extract.ts                # runExtract helper(generateObject 封装)
```

## 7. 分阶段执行

- **P0 环境修正**:`.env` DB_NAME `agent_platform`→`ai_platform_db`;确认 getPool 连通。
- **P1 基础设施**:`ToolDefinition.readonly`;policy 看字段;core/tools 骨架;coreTools 导出。
- **P2 模型约束**:temperature 默认 0.2;COMPACTION_GUIDE 增强 + 工具优先 prompt。
- **P3 压缩折中**:DEFAULT_POLICY 调参;便签不折叠。
- **P4 工具实现**:query_database(含 nl2sql/guard/backend/mssql 适配器)→ observe_state → recall → notes → now → confirm → runExtract。
- **P5 AgentConfig 新字段 + 注册**:database/getState/等;coreTools 在示例项目挂载验证。
- **P6 验证**:tsc 全过;query_database 连 ai_platform_db 端到端跑一轮(生成→guard→执行→真实数据)。

## 8. 验证策略

- tsc 全程保持通过(每个 P 结束跑 `npx tsc --noEmit`)。
- query_database 端到端:连 ai_platform_db,问"最近 10 笔销售订单"/"员工最多的 5 个部门",验证 SQL 正确 + guardSQL 拦截 + 自纠 + trace 透传。
- 压缩折中:不依赖 DB,可单元验证 policy 行为。
- DeepSeek 在线是 generateObject 前提;若 503 则该步降级为类型检查+逻辑审查,其余照验。
